# bmsonto62bms 仕様書

bmson 形式の譜面を、62進数に対応した拡張 BMS に変換するソフトウェアの仕様。
IgusaBmsonStudio（IBS）とは別のソフトウェアとして作る。

- 状態: **確定（第 1 版）**。変更するときは「付録 A. 決定事項の記録」に追記する
- 決定の記録: 「付録 A. 決定事項の記録」

---

## 1. 目的と範囲

### 1.1 目的

bmson で作った譜面を、BMS しか読めないプレイヤーや BMS 前提の配布先でも遊べるようにする。

### 1.2 範囲

| 含める | 含めない |
|---|---|
| bmson → BMS の一方向の変換 | BMS → bmson の変換 |
| スライスごとの音声ファイルの切り出し | 譜面の編集 |
| 変換前後のプレビュー（スライスの試聴、外部 BMS プレイヤーの起動） | 音声のミックスやエフェクト |
| GUI とコマンドラインの両方 | |

### 1.3 入力

- bmson 1.0.0 形式のファイル。IBS で作ったものに限らない
- bmson が参照する音声（WAV / OGG / FLAC / MP3）と BGA の画像・動画
- bmson に書かれた音声ファイルが見つからないときは、同じフォルダで名前が同じ・拡張子だけが違うファイル（.wav → .ogg → .flac → .mp3 の順）を探して使い、警告を出す
  - 例: bmson では `drums.wav` だが、実際には `drums.ogg` しかない → `drums.ogg` を使う
  - 以降はすべて実際のファイルとして扱う（読み方・ビット深度の決め方・`{src}`・画面の「元の音声」）
  - bmson に書かれたファイルがあるときは、それを使う。どの拡張子でも見つからなければエラー

### 1.4 出力

- BMS ファイル 1 つ（拡張子はキーモードで決まる。§5.4）
- 切り出した音声ファイル群（既定では BMS と同じフォルダ。サブフォルダに書き出すこともできる。§6）
- BGA ファイルはコピーせず、元のファイルを相対パスで参照する（§5.7）

## 2. 用語

| 用語 | 意味 |
|---|---|
| スライス | bmson の 1 ノーツが鳴らす音声の区間。bmson は 1 つの音声ファイルの途中から鳴らせるが、BMS はファイルの先頭からしか鳴らせないため、区間ごとに別ファイルへ切り出す |
| パラ音（キー音） | プレイヤーが叩くレーン上のノーツが鳴らすスライス |
| BGM 音 | BGM（bmson の `x` が 0 または未指定）のノーツが鳴らすスライス |
| オブジェクト ID | BMS の `#WAVxx` `#BMPxx` などの `xx`。2 文字 |
| 36進数モード | ID が `01`〜`ZZ`（最大 1295 個）。大文字と小文字は区別しない |
| 62進数モード | `#BASE 62` を宣言し、ID が `01`〜`zz`（最大 3843 個）。大文字と小文字を区別する |

## 3. 62進数 BMS の仕様（調査結果）

出典は「付録 B. 参考資料」。

### 3.1 宣言

- `#BASE 62` を書くと、その BMS は 62進数モードで読まれる
- 62進数で書いた BMS では、この宣言は必須
- 対応しているソフト（2024-04 時点）
  - プレイヤー: beatoraja 0.8.7 以降、mBMplay
  - エディタ: BMSE 2.2.0a、μBMSC（改造版）、BMHelper（改造版）、Mid2BMS（改造版）、sayaslicer

### 3.2 文字の並び

| 文字 | 値 |
|---|---|
| `0`〜`9` | 0〜9 |
| `A`〜`Z` | 10〜35 |
| `a`〜`z` | 36〜61 |

ID の値は「1 文字目 × 62 + 2 文字目」。`00` は「オブジェクトなし」を表すため、使える ID は `01`〜`zz` の 3843 個。

### 3.3 62進数で読まれるもの

`#BASE 62` のとき、次の 7 種類の定義と、それを参照するチャンネルが 62進数で読まれる。

`#WAVxx` `#BMPxx` `#BPMxx` `#STOPxx` `#SCROLLxx` `#SPEEDxx` `#LNOBJ`

### 3.4 62進数にならないもの

| 対象 | 読み方 | 理由 |
|---|---|---|
| 03 チャンネル（旧形式の BPM 変更） | 16進数（`01`〜`FF`） | BPM の値そのものを書くチャンネルのため |
| 地雷（D*・E* チャンネル） | 36進数 | ダメージ量を書くチャンネルのため |

### 3.5 互換性の注意

- 62進数に対応していないプレイヤーは、62進数の BMS を 36進数として読む。`Aa` と `aA` が同じ ID になり、後に定義したほうで上書きされる
- このため、ID が 1295 個に収まるときは 36進数モードで書き出す（§5.3）

## 4. 全体の流れ

1. bmson を読み込む
2. 各ノーツが鳴らすスライスを求める（§5.1）
3. 同じスライスをまとめる（§5.2）
4. ID を割り当て、36進数／62進数のモードを決める（§5.3）
5. スライスを音声ファイルとして書き出す（§6）
6. BMS ファイルを書き出す（§5.4〜§5.8）
7. 必要なら外部 BMS プレイヤーで確認する（§7）

手順 5 と 6 の前に、スライスを試聴して端の処理を確かめられる（§7.1）。

## 5. 変換の規則

### 5.1 スライスの求め方

bmson では、音声チャンネル（`sound_channels` の 1 要素）ごとに、ノーツが鳴ると同じチャンネルで鳴っている音が止まる。
したがって、1 ノーツのスライスは次のようになる。

| 項目 | 求め方 |
|---|---|
| 開始位置 | `c`（継続フラグ）が `false` のノーツは、音声ファイルの先頭（0 秒） |
| | `c` が `true` のノーツは「直前の `c = false` のノーツから、このノーツまでの経過秒数」 |
| 終了位置 | 同じチャンネルで、このノーツより後にある最初のノーツの時刻まで |
| | 後にノーツがなければ、音声ファイルの終わりまで |
| 秒数の計算 | BPM 変化と STOP を含めた実時間 |

- 同じチャンネルで同じ時刻に複数のノーツがある（和音）場合、それらは同じスライスを鳴らす
- ロングノーツ（`l > 0`）でもスライスの区間は変わらない。音の長さは「次のノーツまで」で決まる
- チャンネルの最初のノーツが `c = true` のときは、曲の先頭（0 秒）から鳴り始めていたものとして開始位置を求める
- 同じチャンネルの同じ時刻に鍵盤のノーツ（`x` が 1 以上）と BGM のノーツがあるときは、BGM のノーツを書き出さない（IgusaBmsonStudio のプレビューと同じ扱い。書き出すと同じ音が二重に鳴る）。書き出さなかった数を情報として知らせる
- ロングノーツの終点の音（`up = true` のノーツ）は、`#LNTYPE 1` では表せないため書き出さない。書き出さなかった数を警告として知らせる

### 5.2 同じスライスをまとめる

次の値がすべて一致するスライスは、1 つの音声ファイル・1 つの `#WAV` ID にまとめる。

- 元の音声ファイル
- 開始サンプル位置
- 終了サンプル位置
- 端の処理の設定（§6.3）

チャンネルが違っても、上の値が同じならまとめる。

### 5.3 ID の割り当てとモードの決定

（譜面セットのときの ID の振り方は §5A.4）

1. 種類ごとに必要な ID の数を数える
   - 種類: WAV、BMP、BPM（拡張 BPM）、STOP
   - WAV は「その BMS で使う最大の ID」で数える（譜面が 1 つなら、スライスの数と同じ）
2. どの種類も 1295 個以下なら 36進数モード。`#BASE` は書かない
3. どれか 1 つでも 1295 個を超えたら 62進数モード。ファイル全体に `#BASE 62` を書く
4. どれか 1 つでも 3843 個を超えたら、エラーにして書き出さない。種類と個数をメッセージに示す

- ID は、その ID を最初に使うノーツの時刻順に `01` から振る
- 36進数モードでは `0-9A-Z` だけを使う。62進数モードでは `0-9A-Za-z` を使う

### 5.4 キーモードとチャンネル

対応するモードは beat-7k・beat-14k・popn-9k。`mode_hint` が空なら beat-7k として扱う。ほかのモード（5k / 10k / keyboard など）はエラーにする。

| モード | レーン（bmson の `x`） | `#PLAYER` | 拡張子 | NORMAL の判定幅（§5.8.1） |
|---|---|---|---|---|
| beat-7k | 1〜8 | 1 | `.bme` | 75% |
| beat-14k | 1〜16 | 3 | `.bme` | 75% |
| popn-9k | 1〜9 | 1 | `.pms` | 70% |

bmson の `x` と BMS チャンネルの対応（beatoraja / jbms-parser が bmson と BMS を読むときの割り当てと同じ）:

| bmson `x` | beat-7k | beat-14k | popn-9k |
|---|---|---|---|
| 1〜5 | 11〜15（鍵盤 1〜5） | 11〜15（1P 鍵盤 1〜5） | 11〜15（ボタン 1〜5） |
| 6 | 18（鍵盤 6） | 18（1P 鍵盤 6） | 22（ボタン 6） |
| 7 | 19（鍵盤 7） | 19（1P 鍵盤 7） | 23（ボタン 7） |
| 8 | 16（スクラッチ） | 16（1P スクラッチ） | 24（ボタン 8） |
| 9 | — | 21（2P 鍵盤 1） | 25（ボタン 9） |
| 10〜13 | — | 22〜25（2P 鍵盤 2〜5） | — |
| 14・15 | — | 28・29（2P 鍵盤 6・7） | — |
| 16 | — | 26（2P スクラッチ） | — |
| 0 / なし | 01（BGM） | 01（BGM） | 01（BGM） |
| モードにないレーン | 01（BGM として扱う） | 01（BGM として扱う） | 01（BGM として扱う） |

- ロングノーツ（`#LNTYPE 1`）は、1x チャンネルは 5x、2x チャンネルは 6x に置く（例: 2P スクラッチは 66、pop'n のボタン 9 は 65）
- pop'n の譜面はプレイヤーが拡張子 `.pms` で見分けるため、既定の書き出し先は `.pms` にする。モードと拡張子が合わない名前で書き出すときは警告を出す
- beat-14k は 2P 側（2x チャンネル）のノーツで 14 鍵として読まれる

- モードにないレーン（beat-7k なら `x` が 1〜8 以外、beat-14k なら 1〜16 以外、popn-9k なら 1〜9 以外）のノーツは、無条件で BGM として書き出し、警告で数を知らせる
  - ロングノーツの長さは無視する
  - 同じ位置に鍵盤のノーツがあっても取り消さない（§5.1 の BGM の取り消しは、もとから BGM のノーツだけに当てはめる。もとは鍵盤に置いた音なので、取り消すと音が抜けるため）
- BGM は同じ位置に複数の音を置けるよう、必要な数だけ `#xxx01` の行を重ねる
- ロングノーツは `#LNTYPE 1` を書き、始点と終点の両方に同じ ID を置く。終点用の音は作らない

### 5.5 小節と位置

- 小節の区切りは bmson の `lines` に従う。`lines` がなければ 4 拍（`resolution × 4` パルス）ごとに区切る
- 4/4 でない小節は `#xxx02:<倍率>` を書く。倍率は「小節のパルス数 ÷（`resolution × 4`）」
- 小節の中の位置は、その行に置くすべてのノーツが割り切れる最小の分割数で書く（パルスの最大公約数で約分する）
- 小節番号が 999 を超える場合はエラーにする

### 5.6 BPM と STOP

| bmson | BMS |
|---|---|
| `info.init_bpm` | `#BPM` |
| `bpm_events` | `#BPMxx <値>` と 08 チャンネル。値が整数でも 08 チャンネルを使う |
| `stop_events` | `#STOPxx <値>` と 09 チャンネル |

- STOP の値は「4/4 の 1 小節の 1/192」が単位。`パルス数 × 48 ÷ resolution` で求める
- STOP の値が整数にならないときは、小数のまま書く（例: `#STOP01 37.5`）。beatoraja が小数を読めることを実装時に確かめる

### 5.7 BGA

| bmson | BMS |
|---|---|
| `bga.bga_header` | `#BMPxx <ファイル名>`。ID は振り直す |
| `bga.bga_events` | 04 チャンネル |
| `bga.layer_events` | 07 チャンネル |
| `bga.poor_events` | 06 チャンネル |

BGA のファイルはコピーせず、BMS ファイルからの相対パスを書く。BMS は bmson と同じフォルダに置くのを基本とする。

### 5.8 ヘッダー

| BMS | bmson | 備考 |
|---|---|---|
| `#PLAYER` | `info.mode_hint` | beat-7k・popn-9k は 1、beat-14k は 3（§5.4） |
| `#GENRE` | `info.genre` | |
| `#TITLE` | `info.title` | |
| `#SUBTITLE` | `info.subtitle` | 空なら書かない |
| `#ARTIST` | `info.artist` | |
| `#SUBARTIST` | `info.subartists` | 1 要素につき 1 行 |
| `#BPM` | `info.init_bpm` | |
| `#PLAYLEVEL` | `info.level` | |
| `#DEFEXRANK` | `info.judge_rank` | beatoraja で同じ判定幅になるよう換算する（§5.8.1）。`judge_rank` が 1〜4 なら `#RANK` に書き、0 以下なら書かない |
| `#TOTAL` | `info.total` | 100 なら書かない。100 以外は、beatoraja が bmson を読むときと同じ換算で書く（§5.8.1） |
| `#STAGEFILE` | `info.eyecatch_image` | |
| `#BANNER` | `info.banner_image` | |
| `#BACKBMP` | `info.back_image` | |
| `#PREVIEW` | `info.preview_music` | |
| `#LNTYPE 1` | — | 常に書く |
| `#BASE 62` | — | 62進数モードのときだけ書く |

#### 5.8.1 beatoraja に合わせた換算

beatoraja（BMSPlayerRule）は、判定ランクと TOTAL を次のように読む。

| 入力 | beatoraja での意味 |
|---|---|
| bmson の `judge_rank` J | 判定幅の割合 J % |
| BMS の `#DEFEXRANK` D | NORMAL の判定幅 N（7 鍵・14 鍵は 75 %、pop'n は 70 %）に対する割合。D × N ÷ 100（整数の割り算）% |
| bmson の `total` T | 既定の TOTAL に対する割合 T % |
| BMS の `#TOTAL` | そのままの値。書かなければ既定の TOTAL |

既定の TOTAL は max(260, 7.605 × n ÷ (0.01 × n + 6.5))（n は総ノーツ数。BGM は数えない）。

このため、次のように換算する。

- `#DEFEXRANK` = J × 100 ÷ N の切り上げ（例: 7 鍵で J = 100 → 134。134 × 75 ÷ 100 = 100。pop'n で J = 100 → 143。143 × 70 ÷ 100 = 100）
- `#TOTAL` = T ÷ 100 × 既定の TOTAL（例: T = 120、n = 1000 → 553.090909）

- `info.title_image` と `info.chart_name` に対応する BMS の命令はない。書き出さず、変換結果のメッセージで知らせる
- `#DIFFICULTY` は譜面ごとに利用者が選ぶ（書かない / 1 BEGINNER〜5 INSANE）。1 譜面のときの既定は「書かない」。譜面セットでは `chart_name` から推し量った値が初めに入る（§5A.2）

### 5.9 文字コード

- 既定は Shift_JIS（CP932）
- Shift_JIS で表せない文字がタイトルなどにあれば、警告を出して `?` に置き換える
- 後から UTF-8 でも書き出せるようにする。設計の段階で文字コードを差し替えられる形にしておく

## 5A. 複数難易度の書き出し

同じ曲の複数の難易度の bmson をまとめて読み込み、音声ファイルを共有して、難易度ごとの BMS を書き出す。

### 5A.1 読み込む譜面

- 2 つ以上の bmson を同時に開いたときは「譜面セット」として扱う
- 譜面セットの bmson は、すべて同じフォルダにあること（音声ファイルの名前は bmson のフォルダが基準のため。違うフォルダならエラー）
- 譜面ごとに書き出す BMS は、その bmson の横に `<bmson の名前>.<モードの拡張子>` で書き出す。切り出した音声ファイルは 1 回だけ書き出し、すべての BMS から参照する

### 5A.2 基準の譜面

- 譜面セットを開くと、基準の譜面を選ぶダイアログを出す
  - 一覧に、ファイル名・タイトル・`chart_name`・レベル・鍵盤のノーツ数を並べる
  - 初めに選ばれているのは、レベルが最も高い譜面（同じなら鍵盤のノーツが多い譜面）
  - 同じダイアログで、譜面ごとの `#DIFFICULTY` も決める。初めの値は `chart_name` から推し量る（BEGINNER → 1、NORMAL → 2、HYPER → 3、ANOTHER → 4、INSANE・LEGGENDARIA → 5、分からなければ書かない）
- コマンドラインでは `--base` で基準の譜面を指定する。省くとレベルが最も高い譜面にする
- 基準の譜面の BPM・STOP・小節線・resolution が、ほかの譜面と違うときは警告を出す（別の曲を混ぜたおそれがあるため）

### 5A.3 スライスの共有

- まず、譜面どうしで同じ音の切り出し位置をそろえる。ある譜面のノーツが鳴らす区間の途中で、ほかの譜面（基準の譜面も含む）が切っているときは、短いほうの切り方に合わせる
  - 例: 基準の譜面では 0〜54 秒を 1 つのノーツで鳴らし、ほかの譜面では 0〜50 秒と 50〜54 秒に分けて鳴らすとき、基準の譜面のノーツは 0〜50 秒を鳴らし、50 秒の位置に 50〜54 秒を鳴らす BGM のノーツを加える。逆の場合も同じ
  - 使う切断位置は、同じ時刻に音声の同じ位置を鳴らすものだけ（c=false で先頭からやり直した後の区間は、フレーム番号が同じでも別の時刻を指すため使わない。丸めの差 1 フレームまでは同じとみなす）
  - 切り口はサンプル単位で続くので、鳴る音は変わらない。鍵盤のノーツの音は短くなり、続きは BGM として鳴る
  - 加える BGM のノーツは、同じ位置・同じ区間なら 1 つだけ（和音のノーツで続きが二重に鳴らないように）
  - そろえた譜面ごとに、短く切ったノーツと加えた BGM のノーツの数を情報として知らせる
- そろえた後のすべての譜面のスライスを §5.2 と同じ規則（元の音声・開始・終了が同じなら同じ）でまとめる
- それでも基準の譜面にないスライス（先頭からやり直す位置が違うもの、ほかの難易度だけで鳴らす音）の扱いは、「基準の譜面にないスライスを追加で切り出す」のチェックで決める

| チェック | 扱い |
|---|---|
| あり | 追加で切り出す。譜面ごとに、追加した数と例（小節・元の音声）を情報として知らせる |
| なし（既定） | エラーにして書き出さない。譜面ごとに、基準にないスライスの数と例を知らせる |

### 5A.4 ID と定義

- 同じ音（同じスライス）には、すべての譜面で同じ `#WAV` ID を振る
- ID は、基準の譜面のスライスに最初に鳴る順で振り、追加で切り出したスライスはその後ろに続ける（譜面の順、その中は最初に鳴る順）
- 各 BMS の `#WAV` には、その譜面で使う ID だけを書く（ID は飛び飛びになってよい）
- 36進数か 62進数かは、BMS ごとに「その BMS で使う最大の ID」（と `#BMP`・`#BPM`・`#STOP` の数）で決める（§5.3）。下位の難易度は基準の譜面のスライスの中に収まることが多いため、基準の譜面が 62進数でも 36進数のまま書き出せることが多い
- 名前のパターンの `{song}`・`{measure}` は基準の譜面の曲名・小節で決める。`{id}` は、譜面セットのどれかの BMS が 62進数なら 62進数、すべて 36進数なら 36進数で書く（追加で切り出したスライスの ID が、基準の譜面の進数で表せないことがあるため）。`{index}` はパラ音・BGM 音それぞれで、すべての譜面を通した連番にする
- パラ音か BGM 音かは、どれか 1 つの譜面で鍵盤に置かれていればパラ音とする

## 6. 音声ファイルの書き出し

### 6.1 形式

| 形式 | 内容 |
|---|---|
| WAV | 元の音声と同じサンプルレート・同じビット深度で書き出す（元が 16 bit なら 16 bit、24 bit なら 24 bit、32 bit float なら 32 bit float）。元が FLAC のときも、そのビット深度に合わせる。元が OGG / MP3 のときはビット深度の情報がないため 16 bit にする |
| OGG | libvorbis を組み込んでエンコードする。品質は 0〜10 で指定でき、既定は 5 |

どちらの形式で書き出すかを利用者が選べる。

元の音声の読み方:

| 書き出す形式 | 元の音声 | 読み方 |
|---|---|---|
| WAV | WAV | 元のサンプル形式のまま（8 / 16 / 24 / 32 bit 整数、32 bit 浮動小数点）。切りっぱなしなら、書き出したファイルのサンプルは元の区間とバイト単位で同じ |
| WAV | FLAC | 元のサンプル形式のまま。24 bit の FLAC は 32 bit で読み出されるため、下位 8 bit がすべて 0 なら 24 bit に戻す |
| WAV | OGG / MP3 | 16 bit |
| OGG | どれでも | 32 bit 浮動小数点で読み、エンコードする |

- 元の音声は 1 つにつき 1 回だけ読み、その音声を使うスライスをまとめて書き出す
- 元の音声を読めないときは、その音声のスライスだけを書き出さずにエラーを出す（ほかの音声のスライスは書き出す）
- 長さ 0 のスライス（音声の長さより後を鳴らすノーツ）も、空の音声ファイルとして書き出す
- OGG は同じ入力から同じファイルができるよう、Ogg の通し番号を固定にする

### 6.2 出力先と名前

切り出した音声は、BMS ファイルと同じフォルダ（サブフォルダを決めたときはその下）に書き出す。
名前は次の 3 つのパターン文字列で決める。

| パターン | 既定値 | 例 |
|---|---|---|
| サブフォルダ | 空欄（サブフォルダを作らず、BMS と同じフォルダに書き出す） | `wav` と書けば音声ファイルを `wav/` の下に書き出す（`#WAV` の定義は変えない） |
| パラ音のファイル名 | `{song:.16}_k{index:04}` | `MySong_k0001.wav` |
| BGM 音のファイル名 | `{song:.16}_b{index:04}` | `MySong_b0001.wav` |

拡張子（`.wav` / `.ogg`）は形式に合わせて自動で付ける。パターンには書かない。

BMS の `#WAV` には、サブフォルダの設定にかかわらずファイル名だけを書く（例: `#WAV01 Song_k0001.wav`）。サブフォルダは、書き出した音声ファイルを置く場所だけを変える（`wav` なら `wav/Song_k0001.wav` に書き出す。BMS からは参照できないので、プレイヤーで鳴らすには BMS と同じフォルダに移す）。サブフォルダの名前はパターンで 1 段だけ決められる（`/` は `_` になる）。空にするとサブフォルダを作らず、BMS と同じフォルダに書き出す。

#### 6.2.1 変数

パターンの中の `{変数}` は、スライスごとの値に置き換わる。

| 変数 | 値 | 種類 |
|---|---|---|
| `{song}` | 曲名（`info.title`） | 文字列 |
| `{src}` | 元の音声ファイルの名前（拡張子なし） | 文字列 |
| `{lane}` | そのスライスを最初に使うノーツのレーン（bmson の `x`。BGM は 0） | 数値 |
| `{measure}` | そのスライスを最初に使う小節の番号 | 数値 |
| `{index}` | 連番。パラ音と BGM 音でそれぞれ 1 から、最初に使う時刻の順に振る | 数値 |
| `{id}` | BMS の ID（2 文字） | 文字列 |

- 同じスライスをパラ音と BGM 音の両方で使う場合は、パラ音として扱う（パラ音のパターンと連番を使う）
- `{` そのものを書くときは `{{`、`}` は `}}` と書く

#### 6.2.2 書式

`{変数:書式}` の形で、C 言語の printf の `%` の後ろと同じ書き方で書式を指定できる。

| 書式 | printf での書き方 | 意味 | 例（値） | 結果 |
|---|---|---|---|---|
| `{index:04}` | `%04d` | 4 桁になるまで先頭を 0 で埋める | 7 | `0007` |
| `{index:3}` | `%3d` | 3 桁になるまで先頭を空白で埋める | 7 | `  7` |
| `{index}` | `%d` | そのまま | 7 | `7` |
| `{song:.16}` | `%.16s` | 先頭の 16 文字までにする | `VeryLongSongTitle!` | `VeryLongSongTitl` |

- 数値の変数に使えるのは、`0` フラグと桁数だけ
- 文字列の変数に使えるのは、`.` に続く最大文字数だけ
- 値が指定の桁数より大きいときは切り詰めない（printf と同じ。例: `{index:02}` で 123 → `123`）
- 書式の誤り（数値の変数に `.16` を使う、閉じていない `{` がある、知らない変数を使う、など）は、設定の時点でエラーとして示す

#### 6.2.3 ファイル名として使えない文字と長さ

1. 変数を置き換えたあとで、Windows のファイル名に使えない文字（`\ / : * ? " < > |` と制御文字）を `_` に置き換える
2. 末尾の空白とピリオドを取り除く
3. 拡張子を除いた名前が 64 文字を超える場合は、64 文字に切り詰めて警告を出す
4. 空の名前になった場合はエラーにする

#### 6.2.4 名前がぶつかったとき

- Windows では大文字と小文字を区別せずに比べる。62 進数の ID（`Aa` と `aA` など）を `{id}` で名前にすると、ここでぶつかることがある
- ぶつかった 2 つ目以降には、時刻の順に `_2`、`_3`、… を付ける
- 付けた名前を変換結果のメッセージで知らせる

### 6.3 端の処理

次のどちらかを利用者が選べる。

| 設定 | 内容 |
|---|---|
| 切りっぱなし | 区間をそのまま書き出す。bmson で鳴らした音とサンプル単位で一致する |
| フェード | 切り口に短いフェードをかける。プチノイズは減るが、元の音とは少し変わる |

フェードの設定:

| 項目 | 既定値 | 変えられる範囲 |
|---|---|---|
| フェードアウト（終わり側） | オン、2 ms | 0〜50 ms |
| フェードイン（始まり側） | オフ | オンにしたとき 0〜50 ms |
| カーブ | 直線 | 直線のみ |

- スライスがフェードの長さより短い場合は、フェードの長さをスライスの長さの半分までにする
- `c = false` のスライス（音声ファイルの先頭から鳴らすもの）には、フェードインをかけない

## 7. プレビュー

### 7.1 変換前

- スライスの一覧を表示し、1 つずつ試聴できる。§6.3 の端の処理をかけた音で鳴らす
- 曲全体を、切り出したスライスだけで鳴らして聴ける。bmson で鳴らしたときと同じに聞こえるかを確かめるため
  - すべてのノーツ（パラ音と BGM 音）を、その時刻にスライスを重ねて鳴らす
  - 試聴の音は 32 bit 浮動小数点で作る。書き出す WAV のビット深度とは関係なく、端の処理の効き方を確かめる用途
- 元の音声は一度読んだらとっておき、同じ音声を何度も読まない（別の bmson を開くと読み直す）

### 7.2 変換後

- 書き出した音声ファイルを試聴できる（1 つずつ、曲全体とも）。実際に書いたファイルを読み直して鳴らす
- 書き出した BMS を外部の BMS プレイヤーで開ける（§9.2）
- 書き出した後に設定や書き出し先を変えると「書き出し済み」ではなくなり、書き出したファイルの試聴と外部プレイヤーは、もう一度書き出すまで使えない（画面の設定とファイルの中身が合わなくなるため）

## 8. エラーと警告

| 種類 | 内容 | 扱い |
|---|---|---|
| エラー | ID が 3843 個を超える | 書き出さない |
| エラー | 小節番号が 999 を超える | 書き出さない |
| エラー | 音声ファイルが見つからない、または読めない | 書き出さない |
| エラー | 未対応のキーモード | 書き出さない |
| エラー | 名前のパターンの書式が誤っている、または置き換えた結果が空になる | 書き出さない（bmson や音声を読む前に確かめる） |
| エラー | フェードの長さが 0〜50 ms の外、OGG の品質が 0〜10 の外 | 書き出さない（bmson や音声を読む前に確かめる） |
| エラー | 音声ファイルを書き出せない | そのファイルを書き出さない |
| 警告 | BMS の文字コードで表せない文字が音声ファイルの名前に入る | `_` に置き換える |
| 警告 | ファイル名が 64 文字を超えた | 切り詰めて書き出す |
| 警告 | ファイル名がぶつかった | `_2` などを付けて書き出す |
| 警告 | Shift_JIS で表せない文字がある | `?` に置き換えて書き出す |
| 警告 | BMS に対応する命令がない項目がある（`title_image` など） | 無視して書き出す |
| 警告 | 62進数モードで書き出した | 対応していないプレイヤーがあることを知らせる |

## 9. 設計

IBS と同じ方針で作る。

- MVC に沿ってレイヤーを分け、変換のロジックをファイルや画面から独立させる
  - `core`: 変換ロジック。標準 C++ だけに依存する
  - `infra`: ファイルの読み書き、音声のデコードとエンコード
  - `app`: ユースケース
  - `gui`: Qt の画面
  - `cli`: コマンドライン
- GUI と同じ変換を、コマンドラインからも実行できるようにする（`bmsonto62bms-cli`。§9.3）
- テストの仕様は markdown（`tests/specs/`）に書き、テストに ID を付けて対応させる
- 書く場所のルール: コードには How、テストには What、コミットログには Why、コードコメントには Why not だけを書く

技術スタック（IBS と同じ）: C++20、CMake、Qt 6、miniaudio、stb_vorbis、nlohmann/json、CLI11、GoogleTest。OGG の書き出しのために libvorbis 1.3.7 / libogg 1.3.5（BSD-3-Clause）を加える。どちらもハッシュを確かめてダウンロードし、エンコードに必要なソースだけを静的ライブラリにする。

- IBS のコードは、必要な部分（音声のデコード、bmson の読み込み、時刻の計算など）だけをコピーして独立させる。IBS に依存しない
- リポジトリは IBS とは別に GitHub に作る
- ライセンスは IBS と同じ MIT

### 9.1 画面の構成

設定・プレビュー・書き出しを 1 画面にまとめる。

| 位置 | 内容 |
|---|---|
| 上 | 入力する bmson（「開く…」またはウィンドウへのドロップ。複数選ぶと譜面セット）、表示する譜面の選択と、その譜面の `#DIFFICULTY`、書き出す BMS（既定は bmson の横の `.bme`。譜面ごとに決める） |
| 左 | 書き出しの設定（音声の形式、OGG の品質、名前のパターン 3 つと名前の例、切り口、フェードの長さ、文字コード、基準の譜面にないスライスを追加で切り出すか） |
| 右 | 要約（選んだ譜面の進数と定義の数。使う ID が飛び飛びのときは最大の ID も）、スライスの一覧（ID、種類、ファイル名、元の音声、開始、長さ、最初の小節。譜面セットでは使う譜面の番号も）、試聴（変換前の音／書き出したファイル、選んだスライス・曲全体・停止） |
| 下 | 「書き出す」「外部プレイヤーで開く」、進み具合、メッセージの一覧（エラー・警告・情報） |

- 設定を変えると 0.25 秒後に変換し直し、一覧と名前の例を更新する。名前のパターンの誤りは、その欄の下に赤で出し、「書き出す」を押せなくする
- 使わない設定は押せなくする（フェードの長さは「フェード」のとき、OGG の品質は OGG のときだけ）
- 書き出しは別のスレッドで行い、進み具合を表示する。書き出し中は設定を変えられない
- BMS がすでにあるときは、上書きしてよいか確かめる
- スライスはダブルクリックでも試聴できる
- 譜面セットでは、スライスの一覧に譜面セット全体のスライスを並べる。基準の譜面にないスライスの行には色を付け、選んだ譜面が使わないスライスの行は薄く表示する
- 試聴と外部プレイヤーは選んだ譜面で行う。「書き出す」は譜面セットのすべての譜面を書き出す（音声ファイルは 1 回だけ）。譜面セットの BMS は同じフォルダに書き出す（音声ファイルを共有するため。違うとエラー）

メニュー:

| メニュー | 項目 |
|---|---|
| ファイル | bmson を開く（Ctrl+O）、書き出す（Ctrl+E）、外部プレイヤーで開く（F5）、終了 |
| 設定 | 外部プレイヤー… |
| ヘルプ | 使い方（GitHub）を開く、バージョン情報… |

### 9.2 外部プレイヤー

- beatoraja での確認を想定する
- IBS の Pulsus 連携と同じく、次の 3 つを設定できる

| 項目 | 内容 | 既定 |
|---|---|---|
| 実行ファイル | プレイヤーの実行ファイル | なし（設定するまで起動できない） |
| コマンドライン | `{exe}` は実行ファイル、`{file}` は書き出した BMS の絶対パスに置き換える。先に空白で引数に分けてから置き換えるので、パスに空白があっても 1 つの引数になる | `"{exe}" "{file}"` |
| 作業フォルダ | プレイヤーを起動するフォルダ | 空欄（実行ファイルのフォルダ。beatoraja などは起動したフォルダから設定を読むため） |

- プレイヤーは終了を待たずに切り離して起動する
- BMS をまだ書き出していないときは起動しない

### 9.4 設定の保存

- 画面の設定（書き出しの設定、外部プレイヤー、最後に開いたフォルダ、ウィンドウの位置）は exe の横の `bmsonto62bms.ini` に保存する（IBS と同じポータブル方式）
- パスは `/` 区切りで保存する。ini の `\` はエスケープ文字として扱われ、手で直すときに読みにくいため
- `#DIFFICULTY` は譜面ごとに決めるものなので保存しない（前の曲の値が次の曲に入らないように）

### 9.3 コマンドライン

実行ファイルは `bmsonto62bms-cli`。

| コマンド | 内容 |
|---|---|
| `slices <bmson>... [--json]` | スライスの一覧（ID、パラ音／BGM 音、ファイル名、元の音声、区間。譜面セットでは使う譜面も）を表示する |
| `convert <bmson>... [-o <出力先>] [--bms-only]` | 音声ファイルと BMS を書き出す。出力先を省くと bmson と同じフォルダの `<bmson の名前>.bme`（popn-9k は `.pms`）。`-o` は 1 譜面のときだけ。`--bms-only` では BMS だけを書く |

bmson を 2 つ以上並べると譜面セット（§5A）として変換する。

共通のオプション:

| オプション | 内容 | 既定 |
|---|---|---|
| `--encoding sjis\|utf8` | BMS の文字コード | sjis |
| `--difficulty 1〜5` | `#DIFFICULTY`（1 譜面のときだけ。譜面セットでは `chart_name` から推し量る） | 書かない |
| `--base <bmson>` | 譜面セットの基準の譜面（ファイル名かパス） | レベルが最も高い譜面 |
| `--allow-extra` | 基準の譜面にないスライスを追加で切り出す | 切り出さない（エラー） |
| `--format wav\|ogg` | 音声ファイルの形式 | wav |
| `--quality 0〜10` | OGG の品質 | 5 |
| `--folder <パターン>` | 音声ファイルを書き出すサブフォルダの名前（`#WAV` にはファイル名だけを書く） | 空（BMS と同じフォルダ） |
| `--key-name <パターン>` | パラ音のファイル名 | `{song:.16}_k{index:04}` |
| `--bgm-name <パターン>` | BGM 音のファイル名 | `{song:.16}_b{index:04}` |
| `--edge cut\|fade` | 切り口の処理 | cut |
| `--fade-out <ms>` | フェードアウトの長さ（`--edge fade` のとき） | 2 |
| `--fade-in <ms>` | フェードインの長さ。指定するとフェードインがオンになる | オフ |

終了コード: 0 成功、1 変換のエラー、2 引数の誤り。

## 10. テストの方針

| テスト | 内容 |
|---|---|
| 読み戻し | 書き出した BMS をテスト用の簡単なパーサーで読み戻し、すべてのノーツの時刻とスライスが bmson と一致することを確かめる |
| ID の境界 | 1295 / 1296 / 3843 / 3844 個のときに、モードとエラーが正しく切り替わる |
| 62進数の変換 | 大文字と小文字が別の ID になる |
| 小節 | 変拍子の小節で `#xxx02` と位置が正しい |
| BPM・STOP | 拡張 BPM と STOP の値が正しい |
| スライス | `c` フラグ、和音、最後のノーツ、同じスライスのまとめ方が正しい |
| 音声 | 切りっぱなしのとき、元の音声とサンプル単位で一致する |
| 手動 | 外部の BMS プレイヤーで鳴らして確認する |

## 11. 実装の進め方

| 段階 | 内容 | 状態 |
|---|---|---|
| 1 | bmson の読み込み、スライスの割り出し、ID の割り当て、BMS の書き出し、コマンドライン | 済み |
| 2 | 音声ファイル（WAV / OGG）の書き出し、名前のパターン、フェード | 済み |
| 3 | Qt の画面、試聴、外部プレイヤーの起動 | 済み |
| 4 | 配布用 zip と GitHub のリリース用ワークフロー | 済み |

段階 1・2 で加えた決まり:
- BMS を bmson と別のフォルダに書き出すときは警告を出す（BGA などのファイル名は bmson のフォルダが基準のため）
- 同じレーンの同じ位置にノーツが重なるときは、先のノーツだけを書いて警告を出す
- ロングノーツの終点と、同じレーンの次のロングノーツの始点が同じ位置になるときはエラーにする（`#LNTYPE 1` では区別できないため）

### 11.1 配布

- 配布物は zip 1 つ（`bmsonto62bms-<バージョン>-win64.zip`）。インストーラーはなく、展開したフォルダの直下に exe 2 つ・Qt の DLL・Visual C++ ランタイム・説明・ライセンスを置く
- CPack で作る。Qt の DLL は `qt_generate_deploy_script`（windeployqt）で集め、訳は日本語だけを入れる
- exe にはバージョン情報（ファイルのプロパティ）を埋め込む。`resources/icons/app.ico` があればアイコンも埋め込む
- タグ `v*` を push すると、GitHub Actions が Windows でビルド・テストし、タグと `CMakeLists.txt` の `VERSION` が一致するか確かめてから zip を作り、下書きのリリースに添付する
